# bob_q21img

ROS 2 package and node for the **[Qwen-Image-2.1](https://huggingface.co/Qwen/Qwen-Image-2.1)** text-to-image and image-editing model from the Qwen team.

This package provides a standardized ROS 2 interface for generative image creation and image-to-image editing, following the design principles and topic conventions of the `bob-ros2` robotics ecosystem (similar to `bob_flux2k`).

---

## Features

- **Text-to-Image & Image Editing**: High-quality visual generation driven by a 7B DiT and a Qwen3-VL text/multimodal encoder.
- **Multimodal Prompting**: Accepts plain text strings or JSON payloads supporting single or multiple conditioning reference images (up to 10 input images).
- **Flexible Image Inputs**: Supports local filesystem URIs (`file:///...`), web URLs (`https://...`), and Base64 data strings (`data:image/png;base64,...`).
- **Standard ROS 2 Image Publishing**: Outputs standard `sensor_msgs/msg/Image` (BGR8 encoding) and optionally saves autogenerated PNGs to disk.
- **VRAM Optimizations**: Seamless integration of Model CPU Offloading, Sequential CPU Offloading, and Tiled VAE Decoding to run on 24 GB consumer GPUs (e.g. NVIDIA RTX 4090).
- **Dynamic Parameter Reconfiguration**: Runtime adjustments for inference steps, guidance scale, offloading modes, output paths, and filename counters via ROS 2 parameters (`ros2 param set` or `rqt_reconfigure`).
- **Offline / Local Weight Loading**: Directly loads uncompressed/sharded weights from a local directory without network dependencies or Hugging Face cache overhead.

---

## Supported Model

- **[Qwen/Qwen-Image-2.1](https://huggingface.co/Qwen/Qwen-Image-2.1)**
  - Architecture: 7B Diffusion Transformer (DiT) with Qwen3-VL Text & Vision Encoder.
  - Native resolution: 2048 px class (e.g. 2048×2048, 2400×1792, 1792×2400, 2528×1696).
  - License: Qwen Research License.

If `model_dir` contains local weights (`model_index.json`), the node loads directly from disk with no internet connection required. If `model_dir` does not contain local weights, the node automatically downloads the specified `repo_id` into `model_dir`.

## Installation & Build

### Prerequisites

- ROS 2 (Humble or newer)
- Python >= 3.10
- NVIDIA GPU with CUDA support and matching PyTorch installation (CUDA 12.x recommended)
- System libraries: `ffmpeg`, `libgl1`, `libglib2.0-0`, `libsm6`, `libxext6`
- ROS 2 packages: `cv_bridge`, `std_msgs`, `sensor_msgs`

### Native Workspace Build

1. Clone or place this package into your ROS 2 workspace:
   ```bash
   cd <ros2_ws>/src
   git clone https://github.com/bob-ros2/bob_q21img.git
   ```

2. Install Python dependencies:
   ```bash
   pip3 install -r bob_q21img/requirements.txt
   ```
   *(Note: `diffusers` requires a version supporting `QwenImage21Pipeline`)*.

3. Build the workspace:
   ```bash
   source /opt/ros/${ROS_DISTRO}/setup.bash
   cd <ros2_ws>
   colcon build --packages-select bob_q21img
   source install/setup.bash
   ```

A production-ready `Dockerfile` and `docker-compose.yaml` with NVIDIA GPU reservations and ROS 2 Humble base are included.

### Start Container
```bash
docker compose up -d --build
```

### View Logs
```bash
docker compose logs -f
```

### Stop Container
```bash
docker compose down
```

The Docker setup mounts:
- `./models` -> `/app/models` (read-only model weights)
- `./generated_images` -> `/app/generated_images` (output directory)
- `./config` -> `/app/ros2_ws/src/bob_q21img/config` (editable configuration)

## Usage

### 1. Run the Node

```bash
ros2 run bob_q21img tti --ros-args --params-file src/bob_q21img/config/tti.yaml
```

Or with a specific ROS namespace:
```bash
ros2 run bob_q21img tti --ros-args -r __ns:=/q21img --params-file src/bob_q21img/config/tti.yaml
```

### 2. Send Prompts

#### Plain Text Prompt (Text-to-Image)
```bash
ros2 topic pub /prompt std_msgs/msg/String "{data: 'A futuristic city in the style of cyberpunk, 8k resolution'}" --once
```

#### JSON Prompt (Image-to-Image / Editing)
The node automatically detects JSON formatted messages. The `image_url` field accepts single strings or lists of images:

- **Single reference image:**
  ```json
  {"content": "Change the background to a sunset beach", "image_url": "file:///path/to/image.png"}
  ```

- **Multiple reference images (up to 10):**
  ```json
  {"content": "Place both subjects side by side on a beach", "image_url": ["file:///path/to/a.png", "file:///path/to/b.png"]}
  ```

- **Publishing via CLI:**
  ```bash
  ros2 topic pub /prompt std_msgs/msg/String "{data: '{\"content\": \"a robot dog\", \"image_url\": \"file:///path/to/dog.jpg\"}'}" --once
  ```

Supported URI schemes for `image_url`:
- Local files: `file:///path/to/image.png`
- Web URLs: `https://example.com/input.jpg`
- Base64 data: `data:image/png;base64,...`

## ROS 2 Interface

### Topics

| Topic | Message Type | Direction | Description |
| :--- | :--- | :--- | :--- |
| `prompt` | `std_msgs/msg/String` | **Subscriber** | Input prompt (plain text string or JSON object). |
| `generated_image` | `sensor_msgs/msg/Image` | **Publisher** | Generated image encoded in `bgr8`. |

*Node Name:* `tti` (supports namespacing via `ROS_NAMESPACE` or `-r __ns:=...`).

---

### Memory & Preload Modes

| `preload` | `keep_loaded` | Lifecycle Behavior |
| :--- | :--- | :--- |
| `false` | `true` *(Default)* | Model loads on the first incoming prompt and remains resident in memory. |
| `false` | `false` | Model loads per prompt and unloads immediately after generation (minimal idle VRAM). |
| `true` | `true` | Model preloads during node initialization and stays resident in memory. |
| `true` | `false` | Model preloads at startup, but is unloaded after processing each prompt. |

---

### Parameters

#### Dynamic Parameters (Reconfigurable at runtime via `rqt_reconfigure` or `ros2 param set`)

| Parameter | Environment Variable | Default | Description |
| :--- | :--- | :--- | :--- |
| `keep_loaded` | `Q21IMG_KEEP_LOADED` | `true` | Keep pipeline loaded in VRAM between prompts. |
| `cpu_offload` | `Q21IMG_CPU_OFFLOAD` | `true` | Enable model CPU offloading (essential for 24 GB cards). |
| `sequential_offload` | `Q21IMG_SEQUENTIAL_OFFLOAD` | `false` | Sequential CPU offloading for strict VRAM constraints. |
| `vae_tiling` | `Q21IMG_VAE_TILING` | `true` | Tiled VAE decoding (keeps decode memory peak flat from ~1536 px). |
| `output_resolution` | `Q21IMG_OUTPUT_RESOLUTION` | `0` *(auto)* | Resolution to which reference images are resized before conditioning (`0` = `max(width, height)`). |
| `num_inference_steps` | `Q21IMG_NUM_STEPS` | `40` | Number of denoising diffusion steps. |
| `guidance_scale` | `Q21IMG_GUIDANCE` | `1.0` | Maps to `true_cfg_scale`. Values > 1.0 require `negative_prompt`. |
| `negative_prompt` | `Q21IMG_NEGATIVE_PROMPT` | `""` | Negative prompt text (required when `guidance_scale` > 1.0). |
| `num_images_per_prompt`| `Q21IMG_NUM_IMAGES` | `1` | Number of images to generate per prompt. |
| `frame_id` | `Q21IMG_FRAME_ID` | `q21img` | Frame ID for published ROS image headers. |
| `image_counter_start` | `Q21IMG_IMAGE_COUNTER_START` | `9000` | Starting index for filename counters in `auto` mode; dynamic resets supported. |
| `image_path` | `Q21IMG_IMAGE_PATH` | `generated_images/auto` | Filepath or directory for saving images. Paths ending in `auto` create incrementing filenames. |

#### Static Parameters (Configured at node startup)

| Parameter | Environment Variable | Default | Description |
| :--- | :--- | :--- | :--- |
| `repo_id` | `Q21IMG_REPO_ID` | `Qwen/Qwen-Image-2.1` | Hugging Face repository ID (used when local weights are absent). |
| `model_dir` | `Q21IMG_MODEL_DIR` | `./models` | Directory containing local model weights or cache target. |
| `device` | `Q21IMG_DEVICE` | `cuda:0` | PyTorch execution device. |
| `preload` | `Q21IMG_PRELOAD` | `false` | Preload model during startup instead of waiting for first prompt. |
| `prompt` | `Q21IMG_PROMPT` | `""` | Optional prompt triggered automatically on startup. |
| `input_image` | `Q21IMG_INPUT_IMAGE` | `""` | Static reference image path for editing mode. |
| `seed` | `Q21IMG_SEED` | `-1` | RNG seed (`-1` = random seed per generation). |
| `height` | `Q21IMG_HEIGHT` | `1280` | Generated image height in pixels. |
| `width` | `Q21IMG_WIDTH` | `1280` | Generated image width in pixels. |
| `once` | `Q21IMG_ONCE` | `false` | Automatically terminate node after processing initial prompt. |

## Hardware & VRAM Guide (24 GB Benchmark)

Tested on NVIDIA GeForce RTX 4090 (24 GB VRAM) with `bfloat16`:
- Text/Vision Encoder: ~17.5 GB
- DiT Transformer: ~14.2 GB
- VAE: ~1.4 GB

Because these components cannot fit in 24 GB VRAM simultaneously:
- **`cpu_offload: true`** is required for standard inference (~19 GB peak VRAM).
- Running with `cpu_offload: false` and `sequential_offload: false` will result in a CUDA Out-of-Memory (OOM) error.

### Reference Performance (1024×1024, Model CPU Offload)

| Operation | Steps | Typical Duration |
| :--- | :--- | :--- |
| Model warm load (local NVMe) | - | ~0.5 – 0.8 s |
| Text-to-Image | 12 steps | ~20 s |
| Text-to-Image | 30 steps | ~44 s |
| Image-to-Image / Editing (1 reference) | 30 steps | ~44 s (+ ~13 s encoding) |
| Native 2048×2048 Text-to-Image | 40 steps | ~157 s |

### Image-Guided Runs & Memory Limits on 24 GB

Conditioning images require extra VRAM as they pass through the text/vision encoder and are tokenized into DiT latents:

| Configuration (`output_resolution: 0` = auto) | Status | Notes |
| :--- | :--- | :--- |
| 1024×1024, auto, `cpu_offload: true` | ✅ Works | Clean fusion (20 steps ≈ 39 s) |
| 1536×1536, auto, `cpu_offload: true` | ❌ OOM | Exceeds 24 GB during DiT execution |
| 2048×2048, auto, `cpu_offload: true` | ❌ OOM | Exceeds VRAM during text encoder stage |
| 2048×2048, `output_resolution: 1024`, `cpu_offload: true` | ⚠️ Degraded | Runs, but fails conditioning coherence |
| 2048×2048, auto, **`sequential_offload: true`** | ✅ Works | Clean fusion & sharp details (~13.5 GB peak VRAM) |

> [!TIP]
> **Recommendation for 24 GB cards:** Use `cpu_offload: true` up to 1024×1024 for maximum speed. For resolutions ≥ 1536×1536 or complex multi-image fusion, switch to `sequential_offload: true` with `cpu_offload: false`. Always leave `output_resolution: 0` (auto).

## Quality & Generation Guidelines

1. **Resolution**: Native training resolutions (2048 px class) provide optimal sharpness. Keep `output_resolution: 0` so reference images match the target latent scale.
2. **VAE Tiling**: Enable `vae_tiling: true` for dimensions ≥ 1536 px to prevent memory spikes during decoding. For ≤ 1024 px, `vae_tiling: false` preserves fine pixel details.
3. **Guidance Scale & Negative Prompts**: For strict instruction following in editing tasks, use `guidance_scale: 2.0 - 3.0` paired with a descriptive `negative_prompt`.
4. **Input Image Fidelity**: Provide crisp, high-resolution source images (≥ 2048 px) when conditioning, as noise or compression artifacts are preserved in the latent representation.
